# Описание проекта Space.js Platform

## Общая информация

**Название**: Space.js Platform (NodeCRM)
**Тип**: Enterprise-grade фреймворк для SaaS-приложений
**Версия**: 1.0.0
**Лицензия**: См. LICENSE

## Назначение

Space.js Platform - это современный фреймворк для разработки многопользовательских SaaS-приложений на Node.js. Фреймворк предоставляет готовую инфраструктуру для быстрой разработки масштабируемых приложений с модульной архитектурой, встроенной системой dependency injection, автоматической валидацией данных и hot reload для повышения производительности разработки.

## Основные возможности

### 1. Модульная архитектура
- Изолированные, переиспользуемые модули
- Четкое разделение на providers (сервисы) и consumers (API-эндпоинты)
- Lifecycle hooks для управления жизненным циклом модулей
- Возможность динамического слияния модулей

### 2. Dependency Injection
- Встроенный IoC-контейнер
- Три области видимости: Singleton, Scoped, Transient
- Автоматическое разрешение зависимостей
- Поддержка eager и lazy loading
- Lifecycle методы (postConstructor, dispose)

### 3. Virtual Space
- Динамическая загрузка модулей из файловой системы
- Hot Reload - автоматическая перезагрузка при изменении кода
- Изолированная среда выполнения
- Кастомный require с поддержкой внутренних зависимостей
- Автоматическое отслеживание изменений файлов

### 4. HTTP/2 Server
- Встроенный HTTP/2 сервер с поддержкой TLS
- Автоматическая маршрутизация на основе метаданных
- Поддержка динамических параметров URL
- Обработка streaming данных
- Управление сессиями HTTP/2

### 5. Система валидации
- Декларативная валидация через схемы
- Поддержка примитивных типов (string, number, boolean, date)
- Вложенные объекты и массивы
- Enum-поля
- Возможность создания кастомных валидаторов
- Автоматическая валидация входных и выходных данных

### 6. Контроль доступа
- Встроенная система авторизации
- Предустановленные уровни: public, authenticated, private
- Поддержка кастомных функций проверки доступа
- Интеграция с Session для управления правами
- Role-based и permission-based контроль

### 7. Session Management
- Встроенная система сессий
- Уникальные идентификаторы (UUID)
- Поддержка ролей и прав доступа
- Изолированное хранилище данных на базе Map
- Scope-based sessions для изоляции запросов

## Архитектурные паттерны

### 1. Dependency Injection (IoC)
Все компоненты управляются DI-контейнером, что обеспечивает:
- Слабую связанность компонентов
- Легкую тестируемость
- Контроль жизненного цикла
- Автоматическое разрешение зависимостей

### 2. Module Pattern
Модульная организация кода:
- Логическая группировка компонентов
- Инкапсуляция функциональности
- Переиспользование модулей
- Композиция приложения из модулей

### 3. Command Pattern
API-эндпоинты реализованы как команды:
- Инкапсуляция запроса
- Валидация и авторизация на уровне команды
- Единообразная обработка результатов
- Возможность логирования и мониторинга

### 4. Builder Pattern
Конфигурация приложения через builder:
- Fluent API для настройки
- Поэтапная конфигурация
- Валидация конфигурации перед запуском

### 5. Factory Pattern
Создание сложных объектов:
- Virtual Space factory
- HTTP Server factory
- Plugin factories
- Component factories

### 6. Observer Pattern
Реактивность через события:
- Module change events
- Application lifecycle events
- Plugin integration points

### 7. Result/Optional Monads
Функциональный подход к обработке ошибок:
- Result для операций с возможными ошибками
- Optional для nullable значений
- Композиция операций
- Безопасная обработка null/undefined

## Жизненный цикл приложения

1. **Инициализация**: `Application.build()` создает конфигурацию
2. **Кластеризация**: Создание worker-процессов (опционально)
3. **Загрузка модулей**: Virtual Space сканирует и загружает модули
4. **Построение контейнера**: Регистрация всех компонентов
5. **Инициализация плагинов**: Запуск HTTP-сервера и других плагинов
6. **Построение команд**: Создание API-эндпоинтов из consumers
7. **Bootstrap**: Вызов lifecycle hooks
8. **Готовность**: Приложение готово к обработке запросов

## Жизненный цикл запроса

1. **HTTP Request**: Входящий запрос на HTTP/2 сервер
2. **Parse Request**: Парсинг URL, headers, body
3. **Route Resolution**: Поиск соответствующей команды
4. **Session Creation**: Создание или восстановление сессии
5. **Access Control**: Проверка прав доступа
6. **Body Validation**: Валидация входных данных
7. **Container Scope**: Создание scope для SCOPED компонентов
8. **Dependency Injection**: Разрешение зависимостей команды
9. **Command Execution**: Выполнение бизнес-логики
10. **Result Validation**: Валидация выходных данных
11. **Response Serialization**: Формирование HTTP-ответа
12. **Cleanup**: Освобождение SCOPED ресурсов

## Производительность

### Оптимизации
- **Singleton caching**: Компоненты создаются один раз
- **Lazy initialization**: Создание по требованию
- **Module caching**: Virtual Space кеширует модули
- **HTTP/2 multiplexing**: Эффективная передача данных
- **Cluster mode**: Использование всех CPU-ядер

### Метрики (типичные)
- **Startup time**: < 1s
- **Request latency**: < 10ms (без БД)
- **Throughput**: 10,000+ req/s (зависит от логики)
- **Memory**: ~50-100 MB base + application data

## Сравнение с аналогами

### vs Express.js
✅ Встроенный DI контейнер
✅ Автоматическая валидация
✅ Hot reload из коробки
✅ Модульная архитектура
⚠️ Меньше middleware экосистемы

### vs NestJS
✅ Легче и быстрее
✅ Меньше зависимостей
✅ Virtual Space с hot reload
✅ Простая конфигурация
⚠️ Меньше декораторов

### vs Fastify
✅ Модульная организация
✅ DI контейнер
✅ Встроенная валидация схем
⚠️ HTTP/2 only (не HTTP/1)
⚠️ Меньше плагинов

## Быстрый старт

```bash
# Установка
pnpm install

# Создание сертификатов
mkdir -p certs
openssl req -x509 -newkey rsa:4096 -keyout certs/server.key \
  -out certs/server.crt -days 365 -nodes -subj "/CN=localhost"

# Запуск
node main.js

# Тестирование
curl -k https://localhost:3000/hello
```
